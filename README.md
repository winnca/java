## <a id="title0">1. Что за проект</a>

В данном `README.md` описывается **RESTful веб-сервис (приложение)**, который обрабатывает `HTTP-запросы` и реализует стандартные **CRUD-операции**: `Create`, `Read`, `Update`, `Delete`. В качестве ресурсов используются **"студенты"**.

* `RESTful` — потому что сервис написан с учётом всех обязательных правил `REST`.  

* `REST` = `Representational State Transfer` — это архитектурный стиль взаимодействия сервисов между собой в рамках микросервисной архитектуры или взаимодействия с другими сторонними сервисами.

<br>

## <a id="title1">1.1. Архитектура проекта REST API</a>

`REST` состоит из **6 правил**, которые соблюдает наше приложение:

### 1. Клиент-серверная архитектура

В нашем приложении:

- Клиент — `Postman` (инструмент для отправки `HTTP-запросов` и получения ответов). С его помощью мы тестируем операции `CRUD` по студентам.
- Сервер — `Spring Boot` приложение, а именно встроенный `Tomcat` сервер.

Разделение клиента и сервера позволяет им развиваться независимо.

### 2. Отсутствие состояния

Каждый запрос содержит **всю необходимую информацию** для его обработки. Сервер **не хранит сессию клиента** между запросами. В нашем проекте нет:
- Использования `HttpSession`
- Аннотации `@SessionAttributes`

### 3. Кэширование

Хотя в нашем приложении кэширование не реализовано явно, `Spring` позволяет его добавить с помощью **`@Cacheable`**. Ответы сервера могут помечаться как кэшируемые или нет, что позволяет оптимизировать нагрузку.

**Пример:** в кэше `Redis` могут лежать самые часто запрашиваемые `HTML-документы` (например, страница авторизации на портале), чтобы не нагружать базу данных повторными запросами.

### 4. Единообразие интерфейса

Взаимодействие с ресурсами (студентами) происходит через стандартные методы `HTTP`. В поисковой строке указывается точный `URL` для определённого типа запроса:

| HTTP метод | Аннотация Spring | Назначение | Пример URL из проекта |
|------------|------------------|------------|------------------------|
| `GET` | `@GetMapping` | Чтение данных | `/api/students` или `/api/students/read_student/{email}` |
| `POST` | `@PostMapping` | Создание данных | `/api/students/save_student` |
| `PUT` | `@PutMapping` | Обновление данных | `/api/students/update_student` |
| `DELETE` | `@DeleteMapping` | Удаление данных | `/api/students/delete_student/{email}` |

### 5. Многоуровневая система

Наше приложение разделено на слои:

| Слой | Пакет | Аннотация | Назначение |
|------|-------|-----------|------------|
| `Controller` | `ru.winnca.restcrud.students.controller` | `@RestController` | Обрабатывает `HTTP-запросы`. Является **фасадом** — точкой входа в приложение для клиентов или `API`. Каждый метод помечен специализированной аннотацией (`@GetMapping`, `@PostMapping` и т.д.) и имеет `URL` для точной адресации. |
| `Service` | `ru.winnca.restcrud.students.service` | `@Service` | Уровень бизнес-логики приложения. Выступает посредником между репозиторием и контроллером. Использовать сервис в качестве репозитория или контроллера — некорректно. |
| `Repository` | `ru.winnca.restcrud.students.repository` | `@Repository` | Уровень доступа к данным. Взаимодействует с БД или оперативной памятью `RAM`. |
| `Model` | `ru.winnca.restcrud.students.model` | `@Entity` (для `JPA`) | Уровень данных/cущностей. Представляет, из чего состоит студент, какие у него атрибуты в таблице БД. |

3. `.gitattributes` — файл для настройки `Git`. Указывает, как обрабатывать определённые типы файлов (например, окончания строк).

4. `HELP.md` — предоставляет документацию по умолчанию для `Spring` и библиотек. Файл по умолчанию, а нашу документацию или описание проекта пишем в `README.md`.

5. `src/`

   - `main/java` — содержит всю прописанную нами логику приложения (все слои: `controller`, `service`, `repository`, `model`).

   - `main/resources` — содержит файлы настройки конфигурации (`application.yaml`), а также файлы фронтенда. При реализации паттерна MVC файлы `.html`, `.css`, `.js` хранятся в папке `static`. Папка `templates` предназначена для шаблонов — файлы `thymeleaf`, которые обеспечивают интеграцию с `Java` = **работа с формами** = для отображения фронтенда.

     **Как это работает:** `Spring` приложение при старте загружает конфигурацию из `resources` и сканирует `java`-пакеты в поисках компонентов (`@Controller`, `@Service`, `@Repository` и т.д.).

   - `src/test/` — папка для тестов (`JUnit` и интеграционные тесты для проверки работоспособности приложения).

6. `target/` — папка, куда `Maven` складывает результаты сборки (скомпилированные `.class`-файлы, итоговый `JAR/WAR`). `Git` игнорирует эту папку.

7. `.idea/` — папка с настройками `IntelliJ IDEA`. Хранит конфигурацию запуска, стиль кода, настройки проекта. Не попадает в `Git` (добавлена в `.gitignore`).

8. `.mvn/` — папка с настройками `Maven Wrapper`. Позволяет запускать сборку проекта без предварительной установки Maven на компьютер.

9. `mvnw / mvnw.cmd` — скрипты для запуска `Maven` без его установки. `mvnw` — для `Linux/Mac`, `mvnw.cmd` — для `Windows`.

### <a id="title21">2.1. Для чего используют Maven</a>

#### 1. Что такое `Maven`

**`Maven`** — это сборщик нашего проекта. Он:

- Управляет зависимостями (библиотеками, которые мы подключаем)
- Управляет процессом компиляции (вызывает компилятор Java)
- Запускает тесты
- Упаковывает приложение в `JAR` или `WAR`

Все эти настройки находятся в файле `pom.xml`.

<br>

#### 2. Файл `pom.xml`

`pom.xml` — содержит **метаданные о проекте** и инструкции по его сборке.

**Почему используется `XML`?**
- Поддержка `UNICODE` (многоязычность, исключает "кракозябры")
- Решение проблем совместимости разных программ и операционных систем
- Поддержка современных символов (например, эмодзи)

<br>

Из всех тегов в этом файле нам важны только: `parent`, `groupId`, `artifactId`, `version`.

| Тег | Описание |
|-----|----------|
| `parent` | Тянет все настройки Spring Boot по умолчанию. Если будем создавать модуль внутри нашего приложения, то модуль будет наследовать настройки от родителя. |
| `groupId` | Уникальный идентификатор группы или организации, создавшей проект. Обычно используется перевёрнутое доменное имя (`ru.winnca.restcrud`). Является корнем для всех модулей и библиотек внутри организации. |
| `artifactId` | Уникальное имя самого проекта (артефакта). Соответствует названию выходного файла сборки — например, `students`. |
| `version` | Версия проекта. Указывает, какая версия сейчас в разработке. |

<br>
   
#### 3. Тип сборки = `packaging`

В нашем проекте используется сборка `JAR` = `Java ARchive`:

- В `Spring Boot` уже есть **встроенный сервер `Tomcat`**
- Нам **не нужно** разворачивать отдельный внешний сервер

Существует также сборка `WAR` = `Web ARchive`:

- Используется для веб-приложений, которые развёртываются на **внешнем сервере**
- Примеры внешних серверов: `Apache Tomcat`

`Spring Framework` — это платформа, состоящая из нескольких взаимосвязанных модулей, сгруппированных по функциональному признаку.

<br>

#### 1. Data Access/Integration (Доступ к данным и интеграция)

Модуль, который предоставляет классы, интерфейсы и аннотации для управления доступом к данным. Упрощает взаимодействие с БД и другими источниками данных. Состоит из:

- `JDBC` = `Java Database Connectivity` — стандартный `Java API` для взаимодействия с реляционными базами данных. `Spring` упрощает работу с ним через модуль `spring-jdbc`, убирая шаблонный код.

- `ORM` = `Object-Relational Mapping` — технология отображения `Java-объектов` на таблицы в реляционной базе данных. `Spring` интегрируется с `ORM-фреймворками`, такими как `Hibernate`.

- `OXM` = `Object-XML Mapping` — отображение `Java-объектов` в `XML` и обратно.

- `JMS` = `Java Message Service` — `API` для асинхронного обмена сообщениями между приложениями через брокеры сообщений `RabbitMQ`.

- `Transactions` — модуль для декларативного (через `@Transactional`) и программного управления транзакциями. Реализация декларативных транзакций основана на `AOP`.

<br>

#### 2. Web (MVC/Remoting)

Предоставляет `API` и утилиты для создания веб-приложений. Состоит из:

- `Servlet` — обеспечивает поддержку традиционных веб-приложений на основе `Servlet API`.

- `Web` — базовый веб-модуль, предоставляющий фундаментальную веб-функциональность.

- `Portlet` — интегрирует приложение с `API Portlets` (устаревшая технология, в современных проектах практически не используется).

- `WebSocket` — обеспечивает поддержку двусторонней связи между клиентом и сервером в режиме реального времени.

<br>

#### 3. AOP = Аспектно-ориентированное программирование

Мощный механизм модуляции **сквозных проблем (cross-cutting concerns)** — функциональностей, которые затрагивают несколько компонентов и не могут быть полностью отделены от основной логики (логирование, безопасность, управление транзакциями). `AOP` позволяет выделить их в отдельные **аспекты** и применять прозрачно к нескольким компонентам.

**Пример в нашем проекте:** `@Transactional` — хотя аннотация объявлена в модуле `Transactions`, её работа (создание прокси, открытие и закрытие транзакций, откат при исключениях) реализована именно через `AOP`. Spring создаёт прокси-объект, который оборачивает наш метод и добавляет транзакционное поведение.

<br>

#### 4. Aspects

Предоставляет набор готовых аспектов, которые могут быть использованы в приложении на основе `AOP`. К ним относится ведение журналов, кэширование, безопасность, управление транзакциями. Это модули многократного использования, которые применяются к различным частям приложения для добавления функциональности без ущерба для основного кода.

<br>

#### 5. Instrumentation

Обеспечивает поддержку инструментов байт-кода, позволяя разработчикам изменять поведение скомпилированного класса во время выполнения (например, для целей отладки или мониторинга).

<br>

#### 6. Messaging

Модуль для создания приложений, управляемых сообщениями. Предоставляет абстрактную основу для работы с протоколами обмена сообщениями, такими как **MQTT** = `Message Queuing Telemetry Transport` — облегченный протокол для обмена сообщениями между устройствами.

<br>

#### 7. Core Container (Основной контейнер)

Обеспечивает базовые строительные блоки Spring Framework и включает в себя следующие компоненты:

- `Beans` — предоставляет утилиты для управления компонентами и их зависимостями (основа `IoC`/`DI` = Инверсия контроля/Внедрение зависимостей).

   - `IoC` = `Inversion of Control` — архитектурный паттерн, который передаёт управление объектами фреймворку `Spring`, а не разработчику. Это снижает связанность компонентов.

   - `DI` = `Dependency Injection` — способ реализации `IoC`, при котором объект получает необходимые зависимости извне, а не создаёт их внутри себя.

- `Core` — предоставляет утилиты и неинвазивные способы доступа к низкоуровневым функциональным возможностям Java.

- `Context` — надстройка над модулями `Core` и `Beans` = `ApplicationContext`.

- и другие.

<br>

#### Пример на музыкальном плеере IO/DI.

1. Есть два независимых класса: `ClassicalMusic` и `MusicPlayer`. В плеере есть метод `play()`.

2. **Плохой подход:** Добавляем поле `ClassicalMusic` и создаём объект внутри плеера.  
   - Плеер привязан только к классической музыке.

3. **Рефакторинг:** Создаём интерфейс `Music`. Новые жанры: `RockMusic`, `JazzMusic`, `ClassicalMusic` реализуют этот интерфейс.

4. **Проблема остаётся:** Внутри плеера всё равно создаются объекты конкретных жанров вручную.

5. **Решение — делегируем Spring:**  
   - Помечаем классы аннотацией `@Component`.  
   - Spring сам создаёт объекты = **бины** и управляет их жизненным циклом.

6. **Внедрение зависимостей:**  
   - `Spring` не знает, какие зависимости нужны классу.  
   - Мы **указываем** это через конструктор (лучший способ), поле или сеттер.
   - Над полем ставим аннотацию `@Autowired`.
   - В нашем проекте используем `@AllArgsConstructor` (`Lombok` генерирует конструктор), и `Spring` автоматически внедряет зависимости.

<br>

#### 8. Test

Обеспечивает поддержку тестирования приложений на базе `Spring`. Включает утилиты для написания модульных тестов, интеграционных тестов и сквозных тестов, поддерживает интеграцию с популярными платформами, такими как `JUnit` и другие.

### <a id="title23">2.3. Spring Boot</a>

**Spring Boot** — это проект, построенный на основе Spring Framework, который значительно упрощает и ускоряет разработку приложений.

Основные возможности и преимущества Spring Boot:

- **Автоконфигурация** — `Spring Boot` автоматически настраивает компоненты `Spring` на основе добавленных зависимостей. Например, если в проекте есть `spring-boot-starter-web`, `Spring Boot` автоматически настроит встроенный `Tomcat`. Это избавляет разработчика от написания большого количества `XML-конфигураций` или `Java-конфигураций` вручную.

- **Стартеры** — набор удобных дескрипторов зависимостей (`spring-boot-starter`), которые собирают совместимые версии библиотек для конкретной функциональности. В нашем проекте используется `spring-boot-starter-web` и `spring-boot-starter-data-jpa`.

- **Встроенные серверы** — позволяет запускать приложение как самостоятельный `JAR-файл` со встроенным `Tomcat`. Не требуется устанавливать и настраивать отдельный веб-сервер.

- **Отсутствие шаблонного кода** — минимизирует ручную конфигурацию, позволяя разработчику сосредоточиться на бизнес-логике.

- **Микросервисная архитектура** — `Spring Boot` идеально подходит для создания микросервисов благодаря своей легкости, автономности и простоте развертывания.

**В нашем проекте** мы используем `Spring Boot` для быстрого создания `REST API` без необходимости вручную настраивать `DispatcherServlet`, `DataSource` и другие компоненты — всё это `Spring Boot` делает за нас автоматически.

### <a id="title25">2.5. Жизненный цикл `Spring-приложения`</a>

#### 1. Запуск `JVM`

Процесс начинается с выполнения команды `java -jar students.jar`. Загрузчик классов = `ClassLoader` = загружает в память все необходимые классы, подготавливается среда выполнения `Java`. Управление передаётся методу `main` класса, указанного в манифесте `JAR`.

**В нашем проекте** точкой входа является класс `StudentsApplication` с аннотацией `@SpringBootApplication` и методом `main`, который вызывает `SpringApplication.run()`.

<br>

#### 2. Инициализация Spring Boot

`Запуск SpringApplication.run()`

`Spring Boot` начинает подготовку контекста приложения. Метод `run()` принимает класс с аннотацией `@SpringBootApplication` и запускает весь процесс инициализации.

`Определение главного класса`

Spring анализирует переданный класс `StudentsApplication.class` и находит аннотацию `@SpringBootApplication`. Эта аннотация является составной и включает в себя три важные аннотации:

- `@SpringBootConfiguration` — указывает, что это конфигурационный класс.

- `@EnableAutoConfiguration` — включает автоматическую настройку `Spring Boot` на основе добавленных зависимостей.

- `@ComponentScan` — включает сканирование компонентов в текущем пакете и всех подпакетах.

`Создание ApplicationContext (IoC контейнер)`

Spring создаёт экземпляр `ApplicationContext` — это главное "хранилище" всех бинов (компонентов) приложения. Он отвечает за: cоздание и хранение всех бинов (компонентов), управление жизненным циклом бинов, внедрение зависимостей (DI), ...

`Настройка автоконфигурации`

`Spring Boot` автоматически настраивает компоненты на основе зависимостей, указанных в `pom.xml`. Например, если в проекте есть `spring-boot-starter-web`, `Spring Boot` автоматически настраивает встроенный `Tomcat` и `Spring MVC`. Если есть `spring-boot-starter-data-jpa`, настраивается `Hibernate` и работа с базой данных.

Конфигурационные параметры (например, подключение к базе данных) загружаются из файла `application.yaml`, который лежит в папке `src/main/resources`.

<br>

#### 3. Жизненный цикл бинов

Spring сканирует пакет `ru.winnca.restcrud` (указанный в `@ComponentScan`) и находит классы с аннотациями, которые `Spring` должен превратить в бины:

- `@Repository` — для классов доступа к данным (в нашем проекте это `InMemoryStudentDAO`).

- `@Service` — для классов бизнес-логики (`InMemoryStudentService`).

- `@RestController` — для классов-контроллеров, обрабатывающих `HTTP-запросы` (`StudentController`).

`Создание бинов в порядке зависимостей`

Spring анализирует зависимости между классами. Если один класс зависит от другого (например, `StudentController` зависит от `StudentService`), `Spring` сначала создаст тот бин, который не зависит от других, а затем уже тот, который зависит. В нашем проекте порядок следующий:

1. Сначала создаётся `InMemoryStudentDAO` (у него нет зависимостей).

2. Затем создаётся `InMemoryStudentService` — при его создании Spring внедряет уже готовый бин `InMemoryStudentDAO`.

3. Последним создаётся `StudentController` — при его создании Spring внедряет готовый бин `InMemoryStudentService`.

`Процесс создания каждого бина`

Процесс создания каждого бина проходит через несколько этапов:

1. **Определение бина** — Spring создаёт объект `BeanDefinition`, который хранит метаданные о классе (имя, область видимости, зависимости).

2. **Создание объекта** — Spring вызывает конструктор класса, создавая экземпляр объекта.

3. **Внедрение зависимостей** — Spring анализирует параметры конструктора (или поля с `@Autowired`) и подставляет нужные зависимости из контейнера.

4. **Вызов init-метода** — если в классе есть метод с аннотацией `@PostConstruct`, Spring вызывает его. Здесь можно выполнить дополнительную логику инициализации, например проверить подключение к базе данных.

5. **Бин готов** — полностью инициализированный объект помещается в `ApplicationContext` и становится доступным для использования.

<br>

#### 4. Запуск веб-сервера (Tomcat)

После того как все бины созданы и инициализированы, Spring Boot запускает встроенный веб-сервер. По умолчанию это Apache Tomcat, который стартует на порту 8080.

В консоли появляется сообщение о том, что Tomcat запущен и приложение готово к работе: `Tomcat started on port(s): 8080 (http)`, а затем `Started StudentsApplication in несколько секунд`.

<br>

#### 5. Обработка HTTP-запросов (работа приложения)

Приложение входит в активную фазу работы. Postman (или браузер) отправляет HTTP-запросы к эндпоинтам, которые реализованы в `StudentController`:

- `GET /api/students` — получение списка всех студентов.

- `POST /api/students/save_student` — создание нового студента.

- `GET /api/students/read_student/{email}` — получение студента по `email`.

- `PUT /api/students/update_student` — обновление данных студента.

- `DELETE /api/students/delete_student/{email}` — удаление студента.

**Как обрабатывается запрос (на примере GET /api/students):**

1. Клиент отправляет `HTTP-запрос` на сервер.

2. `DispatcherServlet` (главный сервлет `Spring MVC`) принимает запрос.

3. `HandlerMapping` находит соответствие между `URL` и методом контроллера — `findAllStudents()`.

4. `DispatcherServlet` вызывает метод `findAllStudents()` у `StudentController`.

5. Контроллер делегирует выполнение сервису `StudentService`.

6. Сервис вызывает метод репозитория `StudentRepository` (или `InMemoryStudentDAO`).

7. Репозиторий обращается к источнику данных (база данных или оперативная память) и возвращает результат.

8. Результат проходит обратный путь: репозиторий → сервис → контроллер.

9. Контроллер возвращает объект (например, список студентов) в `DispatcherServlet`.

10. `Jackson` (библиотека для работы с `JSON`) автоматически конвертирует `Java-объект` в `JSON-формат`.

11. `DispatcherServlet` отправляет `HTTP-ответ` (`JSON` + статус `200 OK`) обратно клиенту.

Этот процесс повторяется для каждого входящего запроса на протяжении всей работы приложения.

<br>

#### 6. Получение сигнала на остановку

Приложение может остановиться по разным причинам:

- **Ручная остановка** — пользователь нажимает `Ctrl+C` в консоли (это самый частый случай)
- **Штатное завершение** — приложение самостоятельно вызвало `System.exit(0)`
- **Принудительное завершение** — процесс завершён через диспетчер задач (Task Manager) или команду `kill`

`Spring Boot` перехватывает сигнал на остановку и начинает процесс `graceful shutdown` — плавное завершение, при котором приложение успевает корректно освободить ресурсы.

<br>

#### 7. Завершение работы бинов

Spring начинает уничтожать бины **в обратном порядке** — сначала уничтожаются те бины, которые зависят от других, а затем уже независимые бины.

В нашем проекте порядок уничтожения следующий:

1. Сначала уничтожается `StudentController` (он зависит от сервиса)
2. Затем уничтожается `InMemoryStudentService` (он зависит от `DAO`)
3. Последним уничтожается `InMemoryStudentDAO` (у него нет зависимостей)

Если в классах есть методы с аннотацией `@PreDestroy`, Spring вызывает их перед уничтожением бина. В этих методах можно освободить ресурсы: закрыть файлы, закрыть соединения с базой данных, завершить потоки выполнения ...

<br>

#### 8. Остановка `Spring контейнера`

После того как все бины уничтожены, Spring закрывает `ApplicationContext` — `IoC контейнер` завершает свою работу. Освобождаются все ресурсы, занятые контейнером. `Tomcat` останавливается и больше не принимает новые `HTTP-запросы`.

В консоли может появиться сообщение о закрытии контекста: `Closing org.springframework.context.annotation.AnnotationConfigApplicationContext`.

<br>

#### 9. Остановка JVM

После закрытия `ApplicationContext` управление возвращается к виртуальной машине `Java` =  `JVM`. Если нет активных пользовательских потоков, `JVM` завершает свою работу.

В консоли появляется сообщение: `Process finished with exit code 0`, что означает успешное завершение работы приложения.

<br>

#### Ключевой вывод

**Жизненный цикл приложения — это "контейнер", внутри которого происходит множество жизненных циклов отдельных бинов.** Бины создаются при старте приложения, живут внутри него (обрабатывая запросы) и уничтожаются при его остановке.

## <a id="title3">3. Зависимости проекта</a>

**Зависимости** — это внешние библиотеки и модули, которые подключаются к проекту. Spring Boot управляет их версиями автоматически, что упрощает разработку.

<br>

### <a id="title31">3.1. Spring Web</a>

Стартовый пакет (starter) для создания веб-приложений. Он включает в себя все необходимые компоненты для обработки `HTTP-запросов` и создания `REST API`.

**Что входит в состав Spring Web:**

| Компонент | Описание |
|-----------|----------|
| `Spring MVC` | Фреймворк, реализующий паттерн `MVC`. Создаём контроллеры (`@RestController`) для обработки HTTP-запросов. |
| `Библиотека Jackson` | Обеспечивает **сериализацию** (`Java → JSON`) и **десериализацию** (`JSON → Java`). Подтягивается через `spring-boot-starter-json`. |
| `Базовые модули Spring` | `spring-core`, `spring-beans`, `spring-context` — фундамент для внедрения зависимостей (DI) и управления жизненным циклом бинов. Подтягиваются транзитивно через `spring-web`. |
| `Hibernate Validator` | Реализация `Bean Validation` для проверки корректности данных. Входит через `spring-boot-starter-validation`. |
| `Логирование` | `Logback`, `SLF4J` — библиотеки для логирования работы приложения. Входят через `spring-boot-starter-logging`. |

> **Важно:** Встроенный сервер `Tomcat` — это не часть Spring Web, а часть Spring Boot. Когда мы подключаем `spring-boot-starter-web`, он автоматически тянет за собой `spring-boot-starter-tomcat`, который и обеспечивает запуск встроенного сервера. Благодаря этому приложение можно запускать как самостоятельный JAR-файл без установки отдельного `Tomcat`.

<br>

### <a id="title32">3.2. Lombok</a>

`Lombok` — это библиотека, которая позволяет сократить шаблонный код в `Java-классах` с помощью аннотаций. Вместо того чтобы вручную писать геттеры, сеттеры, конструкторы и другие стандартные методы, мы просто ставим аннотацию.

**Основные аннотации Lombok, используемые в проекте:**

* **`@Data`** — "золотая пуля". Включает в себя сразу несколько аннотаций: `@ToString`, `@EqualsAndHashCode`, `@Getter` (для всех полей), `@Setter` (для всех не final полей) и `@RequiredArgsConstructor`. Делает класс изменяемым (mutable).

* **`@Builder`** — реализует паттерн проектирования "Строитель". Позволяет создавать объекты с большим количеством полей более читаемым и гибким способом (как в примере с `Student.builder().firstName(...).build()`).

* **`@NonNull`** — аннотация для поля или параметра. Добавляет проверку на `null` в сгенерированный конструктор или метод. Если передать `null`, будет выброшено исключение `NullPointerException`.

* **`@AllArgsConstructor`** — генерирует конструктор, который принимает **все** поля класса в качестве аргументов.

   * **Важно для `Spring`:** В нашем проекте мы используем `@AllArgsConstructor` в контроллере (`StudentController`) и сервисе (`StudentServiceImpl`). Spring автоматически выполнит **внедрение зависимостей через конструктор**. То есть, когда `Spring` будет создавать бин `StudentController`, он увидит единственный конструктор со всеми параметрами и автоматически передаст в него нужные зависимости (в нашем случае — `StudentService`). Это считается лучшей практикой, и нам **не нужно** явно писать `@Autowired` над конструктором — Spring сам его вызовет.

* **`@NoArgsConstructor`** — генерирует конструктор без аргументов.

* **`@Getter` / `@Setter`** — генерируют геттеры и сеттеры для полей класса.

**Почему это удобно:** `Lombok` значительно сокращает объем кода, уменьшает риск ошибок и делает классы более чистыми и читаемыми. В сочетании с внедрением зависимостей через конструктор (который генерирует `@AllArgsConstructor`) код становится не только компактным, но и более тестируемым и соответствующим лучшим практикам `Spring`.

<br>

### <a id="title33">3.3. Spring Data Jpa</a>

**Что это:** Стартер Spring Boot для работы с JPA (Java Persistence API).

* `JPA` = `Java Persistence API` = спецификация (набор интерфейсов и правил) для управления реляционными данными в `Java-приложениях`. Она определяет, как `Java-объекты` могут быть отображены на таблицы базы данных и как с ними работать. Сама `JPA` не содержит реализации — это только стандарт.

* `Hibernate` = самая популярная реализация спецификации `JPA`. Именно `Hibernate` выполняет всю низкоуровневую работу:
- преобразует `Java-классы` в таблицы базы данных
- преобразует вызовы методов в `SQL-запросы`
- ...

**Что включает:**
- `Hibernate` — реализация `JPA` для `ORM` = `Object-Relational Mapping`
- `Spring Data JPA` — упрощает создание репозиториев с минимальным кодом
- автоматическую конфигурацию `JPA` и управление транзакциями

Зачем нужен:

* позволяет работать с базой данных через `Java-объекты`, а не писать `SQL-запросы` вручную. Достаточно создать интерфейс репозитория, и `Spring Data JPA` сам реализует основные CRUD-операции.

<br>

### <a id="title34">3.4. PostgreSQL Driver</a>

**Что это:** JDBC-драйвер для подключения к PostgreSQL.

**Особенности:**
- `scope`: `runtime` — драйвер нужен только во время выполнения приложения
- Обеспечивает низкоуровневое соединение между `Java` и `PostgreSQL`
- Позволяет `Spring Boot` определять тип базы данных по `URL` подключения

**Зачем нужен:** Без этого драйвера приложение не сможет установить соединение с `PostgreSQL`, даже если настроен `JPA`.

### Почему нужны обе зависимости?

| `spring-boot-starter-data-jpa` | `postgresql` |
|------------------------------|------------|
| Предоставляет ORM-функциональность | Обеспечивает соединение с конкретной БД |
| Абстракция для работы с данными | Реализует низкоуровневый протокол |
| Не зависит от конкретной СУБД | Зависит от типа базы данных |

* `Spring Data JPA` работает с любой реляционной базой данных, но для каждой нужен свой `JDBC-драйвер`. Поэтому мы добавляем оба: один `для удобной работы с данными`, второй — `для связи с PostgreSQL`.

## <a id="title4">4. application.yaml</a>

1. `name: students` — задаёт имя приложения. Используется для идентификации в логах, `service registry` (например, `Eureka`) - микросервисная архитектура.

```
spring:
  application:
    name: students
```

2. `indent-output: true` — форматирует `JSON-ответы` с отступами. Делает вывод в `Postman` и браузере читаемым. Для продакшена обычно отключают для экономии трафика.

```
  jackson:
    serialization:
      indent-output: true
```

3. `url` — строка подключения к базе данных:

* `jdbc:postgresql://` — протокол = `JDBC` для `PostgreSQL`.

* `localhost` — хост = где запущена БД.

* `5432` — порт = стандартный для `PostgreSQL`.

* `student_db` — имя базы данных.

```
  datasource:
    url:
      jdbc:postgresql://localhost:5432/student_db
```

4. `username` — имя пользователя для подключения к `PostgreSQL`.

```
    username:
      postgres
```

5. `password `— пароль пользователя `PostgreSQL`.

```
    password:
      12345678
```

6. `driver-class-name` — указывает полное имя класса `JDBC-драйвера`. `Spring Boot` может определить его автоматически по `URL`, но явное указание повышает надёжность.

```
    driver-class-name: org.postgresql.Driver
```

7. `ddl-auto: create` — политика управления схемой базы данных:

* `create` — при каждом запуске удаляет существующие таблицы и создаёт заново (данные теряются).

* `create-drop` — создаёт таблицы, а при остановке приложения удаляет их.

* `update` — обновляет схему без удаления данных (добавляет новые колонки/таблицы).

* `validate` — проверяет, что схема соответствует сущностям, но не меняет её.

* `none` — отключает автоматическое управление схемой.

```
  jpa:
    hibernate:
      ddl-auto: create
```

8. `database` — явно указывает тип базы данных. `Spring Boot `может определить автоматически, но явное указание исключает ошибки.

```
    database: postgresql
```

9. `database-platform` — диалект `Hibernate`. Сообщает `Hibernate`, какие `SQL-конструкции` и типы данных поддерживает конкретная СУБД. Например, `PostgreSQL` использует `LIMIT` вместо ROWNUM, и диалект генерирует правильные запросы.

```
    database-platform: org.hibernate.dialect.PostgreSQLDialect
```

10. `show-sql: true` — выводит сгенерированные `SQL-запросы` в консоль. Полезно для отладки, чтобы видеть, какие запросы `Hibernate` отправляет в базу.

```
    show-sql: true
```

11. `format_sql: true` — форматирует `SQL-запросы` в логах с отступами и переносами строк. Работает только вместе с `show-sql: true`.

```
    properties:
      hibernate:
        format_sql: true
```

* Без форматирования:

```
INSERT INTO Students (email,first_name,last_name) VALUES (?,?,?)
```

* С форматированием:

```
INSERT
INTO
    Students
    (email, first_name, last_name) 
VALUES
    (?, ?, ?)
```

Полный:

* `application.yaml` — это файл конфигурации `Spring Boot`, в котором задаются настройки приложения.

```
spring:
  application:
    name: students
  jackson:
    serialization:
      indent-output: true
  datasource:
    url:
      jdbc:postgresql://localhost:5432/student_db
    username:
      postgres
    password:
      12345678
    driver-class-name: org.postgresql.Driver
  jpa:
    hibernate:
      ddl-auto: create
    database: postgresql
    database-platform: org.hibernate.dialect.PostgreSQLDialect
    show-sql: true
    properties:
      hibernate:
        format_sql: true
```

11. Хранение объектов в сервисе некорректно, лучше делать этого через репозитории. Своего рода классы, обеспечивающие доступ к данным. Либо взаимодействует с базой данных (MySQL, PostgreSQL, ...) или с памятью.

<details>

    <br>

    package ru.winnca.restcrud.students.repository;
    import org.springframework.stereotype.Repository;
    import ru.winnca.restcrud.students.model.Student;
    import java.util.ArrayList;
    import java.util.List;
    import java.util.stream.IntStream;
    
    @Repository
    public class InMemoryStudentDAO {
        private final List<Student> STUDENTS = new ArrayList<>();
        public List<Student> findAllStudents(){
            return STUDENTS;
        }
        public Student saveStudent(Student student) {
            STUDENTS.add(student);
            return student;
        }
        public Student readStudent(String email) {
            return STUDENTS.stream().filter(student -> student.getEmail().equals(email)).findFirst().orElse(null);
        }
        public Student updateStudent(Student student) {
            var studentIndex = IntStream.range(0, STUDENTS.size()).filter(index -> STUDENTS.get(index).getEmail().equals(student.getEmail())).findFirst().orElse(-1);
            if (studentIndex > -1){
                STUDENTS.set(studentIndex, student);
                return student;
            }
            return null;
        }
        public void deleteStudent(String email) {
            var student = readStudent(email);
            if (student != null){
                STUDENTS.remove(student);
            }
        }
    }

25. Создадим сервис для взаимодействия с этим репозиторием. Пометим аннотацией @Primary - главный сервис для взаимодействия, если бд прекратит свою работу, то будет работать второй сервис.

<details>
    <summary>code</summary>
    <br>

    package ru.winnca.restcrud.students.service.db;
    
    import jakarta.transaction.Transactional;
    import lombok.AllArgsConstructor;
    import org.springframework.context.annotation.Primary;
    import org.springframework.stereotype.Service;
    import ru.winnca.restcrud.students.model.Student;
    import ru.winnca.restcrud.students.repository.StudentRepository;
    import ru.winnca.restcrud.students.service.StudentService;
    
    import java.util.List;
    
    @Service
    @AllArgsConstructor
    @Primary
    public class StudentServiceImpl implements StudentService {
    
        private final StudentRepository studentRepository;
        @Override
        public List<Student> findAllStudents() {
            return studentRepository.findAll();
        }
    
        @Override
        public Student saveStudent(Student student) {
            return studentRepository.save(student);
        }
    
        @Override
        public Student readStudent(String email) {
            return studentRepository.findByEmail(email).orElse(null);
        }
    
        @Override
        public Student updateStudent(Student student) {
            if (student.getId() != null && studentRepository.existsById(student.getId())){
                return studentRepository.save(student);
            }
            return null;
        }
    
        @Override
        @Transactional
        public void deleteStudent(String email) {
            Student student = readStudent(email);
            if (student != null){
                studentRepository.deleteById(student.getId());
            }
        }
    }
